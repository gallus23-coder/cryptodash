> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Charts tab (design §8.1) against Part C's API: candlestick chart with 1h/4h/1d toggle, EMA20/50/200 and Bollinger overlays, trade/candidate markers, open-position stop/trail lines, a regime band, and an RSI/ADX panel — using the vendored `lightweight-charts` library.

**Architecture:** Two small API gaps need closing before any chart can render real indicator overlays or position lines: there's no endpoint returning EMA/Bollinger/RSI/ADX values (Task 1 adds `GET /api/indicators/:coin`, reusing `src/engine/indicators.js`'s existing pure functions directly — no reimplementation, same "engine code" the backtest/live cycle already share), and there's no endpoint for currently open positions at all (Task 2 adds `GET /api/positions`, reading `scheduler_state`'s `openPositions` array). Everything after that is UI: one `chart.mjs` module owns the `lightweight-charts` instance and candle series, with overlay/marker/band logic split into small testable pure functions in `format.mjs` (trail-stop-level computation, marker-shape mapping, regime-band segment building) plus thin DOM-wiring code that fetches and draws, following the same split this session's Decision-log-tab plan established.

**Tech Stack:** Express (existing API), vanilla JS ES modules (`.mjs`), vendored `lightweight-charts` v5.3.0 (standalone ESM build, already committed under `public-v2/vendor/`), `node --test` for the extractable pure logic.

**Spec:** `docs/v2-design.md` §8.1 (Charts tab). `CLAUDE.md`'s "backtest and live run identical engine code" (extended here to "chart display uses identical engine code," motivating Task 1's reuse of `src/engine/indicators.js` rather than a browser reimplementation).

**Depends on:** `docs/superpowers/plans/2026-11-20-charts-api.md` (Part C — `/api/candles`, `/api/markers`, `/api/regime/*`), `docs/superpowers/plans/2026-11-19-decision-log-ui.md` (Part B — `public-v2/js/api.mjs`'s `fetchJson`, `public-v2/index.html`'s shell, the `.mjs`-everywhere convention). ## Global Constraints

- No CDN — `lightweight-charts` is loaded from `public-v2/vendor/lightweight-charts.standalone.production.mjs`, already vendored.
- Every new endpoint scopes by `mode` where applicable (positions) — matching every prior dashboard endpoint.
- `.mjs` everywhere for browser-loaded files, consistent with Part B's convention.

## Interpretation decisions

- **Funding is omitted from the indicator panel.** Design §8.1 lists "RSI / ADX / funding" — Kraken Futures' funding data was never wired into ingestion (a documented gap from milestone 6 Part A: candidate `context` omits `funding`/`oiChange24h` for the same reason). There is nothing to display; the panel shows RSI and ADX only, with funding deferred to whenever futures ingestion is built.
- **EMA200 is computed on whatever timeframe is currently selected (1h/4h/1d), not cross-referenced from daily data the way the regime engine's `dailyEma200Aligned` does.** The regime engine's daily-EMA200 alignment (milestone 3) exists to avoid look-ahead bias in a trading decision; a chart overlay is a display convenience with no look-ahead-bias concern (the user is looking at history, not making a forward decision from it), so the simpler same-timeframe computation is correct for this purpose and doesn't need the regime engine's alignment machinery.
- **The open-position trail-stop line is computed client-side from already-fetched position + candle data**, not a new API field, since the exact current trail level depends on the highest high since entry — data the browser already has (the same 1h candles `evaluateExit` would scan) once it has the position's `entryTs`/`initialStopPrice`/`atrAtEntry`/`trailAtr`. This mirrors `evaluateExit`'s own formula (`Math.max(initialStopPrice, highestHigh - trailAtr*atrAtEntry)`) as a small pure function, kept in sync by being the same formula, not a duplicated API round-trip.
- **`GET /api/positions` returns the raw `openPositions` array from `scheduler_state`**, not a reshaped/joined view — every field the chart (or a later Strategy-tab reuse) needs is already on the position object `tryOpenPosition` builds (`coin`, `setup`, `entryPrice`, `initialStopPrice`, `atrAtEntry`, `trailAtr`, `exitType`, `targetPrice`, `entryTs`, `candidateId`).

## Review Focus

- A coin/timeframe combination with fewer candles than an indicator's warmup period (e.g. EMA200 needs 200 bars) must render the chart with `null`-gapped indicator lines for the warmup period, not throw or silently show a flat zero line — `src/engine/indicators.js`'s functions already return `null` for warmup bars; the chart renderer must skip `null` points rather than plotting them as `0`.
- The regime band must render every real segment including `risk_off` (the common case) with a visually distinct color — a band that only colors "interesting" regimes and leaves `risk_off` the same as "no data" would look like a monitoring gap.
- A coin with zero open positions must render the chart with no stop/trail lines at all, not a line at `0` or `undefined`.
- Switching the timeframe toggle (1h/4h/1d) must re-fetch both candles and indicators for the new timeframe — a stale set of indicator values computed for the old timeframe overlaid on new-timeframe candles would misrepresent the data.
- The candidate-marker hover text must distinguish "Claude took it," "Claude skipped it," and "fallback (no decision made)" — collapsing all three into one generic "candidate here" tooltip would hide exactly the information this tab exists to surface.

```js
function toPoints(ts, values) {
  return ts.map((t, i) => ({ time: t, value: values[i] })).filter((p) => p.value !== null);
}

export async function renderIndicatorOverlays() {
  try {
    const data = await fetchJson(`/api/indicators/${getCoin()}`, { tf: getTf() });
    const toggles = {
      ema20: document.getElementById('toggle-ema20').checked,
      ema50: document.getElementById('toggle-ema50').checked,
      ema200: document.getElementById('toggle-ema200').checked,
    };
    for (const [key, enabled] of Object.entries(toggles)) {
      if (enabled && !overlaySeries[key]) {
        overlaySeries[key] = chart.addSeries(LineSeries, { lineWidth: 1 });
      }
      if (!enabled && overlaySeries[key]) {
        chart.removeSeries(overlaySeries[key]);
        delete overlaySeries[key];
      }
      if (overlaySeries[key]) overlaySeries[key].setData(toPoints(data.ts, data[key]));
    }

    const bollingerOn = document.getElementById('toggle-bollinger').checked;
    for (const key of ['bollingerUpper', 'bollingerMiddle', 'bollingerLower']) {

      if (!bollingerOn && overlaySeries[key]) { chart.removeSeries(overlaySeries[key]); delete overlaySeries[key]; }
      if (overlaySeries[key]) overlaySeries[key].setData(toPoints(data.ts, data[key]));
    }
  } catch (err) {
    console.error('Could not load indicators:', err.message);
  }
}

['toggle-ema20', 'toggle-ema50', 'toggle-ema200', 'toggle-bollinger', 'coin-select', 'tf-select'].forEach((id) => {
```

```js
export function computeTrailStopLevel(position, candlesSinceEntry) {
  const highestHigh = candlesSinceEntry.reduce((max, c) => Math.max(max, c.high), -Infinity);
  if (highestHigh === -Infinity) return position.initialStopPrice;
  return Math.max(position.initialStopPrice, highestHigh - position.trailAtr * position.atrAtEntry);
}

export function buildTradeMarker(trade) {
  const color = trade.r >= 0 ? '#22c55e' : '#ef4444';
  return [
    { time: trade.entryTs, position: 'belowBar', shape: 'arrowUp', color: '#8b92a5', text: 'entry' },
    { time: trade.exitTs, position: 'aboveBar', shape: 'arrowDown', color, text: `${trade.exitReason} ${formatR(trade.r)}` },
  ];
}

export function buildCandidateMarker(candidate) {
  const { decision } = candidate;
  let text;
  if (!decision) text = `${candidate.setup}: no decision recorded`;
  else if (decision.model === 'fallback') text = `${candidate.setup}: fallback (Claude call failed)`;
  else if (decision.action === 'take') text = `${candidate.setup}: Claude took it`;
  else text = `${candidate.setup}: Claude skipped it`;
  return { time: candidate.ts, position: 'inBar', shape: 'circle', color: '#8b92a5', size: 0.5, text };
}
```

```js
export const REGIME_COLORS = { trend_up: '#22c55e', range: '#d97706', downtrend: '#ef4444', risk_off: '#6b7280' };

export function buildRegimeSegments(historyRows) {
  const segments = [];
  for (const row of historyRows) {
    const last = segments[segments.length - 1];
    if (last && last.label === row.label) {
      last.toTs = row.ts;
    } else {
      segments.push({ fromTs: row.ts, toTs: row.ts, label: row.label });
    }
  }
  return segments;
}
```

Create `public-v2/js/regime-band.mjs`:

```js
import { fetchJson } from './api.mjs';
import { buildRegimeSegments, REGIME_COLORS } from './format.mjs';

export async function renderRegimeBand() {
  const el = document.getElementById('regime-band');
  try {
    const rows = await fetchJson('/api/regime/history', {});
    const segments = buildRegimeSegments(rows);
    const span = (segments[segments.length - 1]?.toTs || 1) - (segments[0]?.fromTs || 0) || 1;
    el.innerHTML = segments.map((s) => {
      const widthPct = ((s.toTs - s.fromTs + 1) / span) * 100;
      return `<span style="display:inline-block;height:100%;width:${widthPct}%;background:${REGIME_COLORS[s.label] || '#000'};" title="${s.label}"></span>`;
    }).join('');
  } catch (err) {
    el.textContent = `Could not load regime history: ${err.message}`;
  }
}

export async function renderIndicatorPanel(coin, tf) {
  const el = document.getElementById('indicator-panel');
  try {
    const data = await fetchJson(`/api/indicators/${coin}`, { tf });
    const lastRsi = data.rsi14[data.rsi14.length - 1];
    const lastAdx = data.adx14[data.adx14.length - 1];
    el.textContent = `RSI(14): ${lastRsi !== null ? lastRsi.toFixed(1) : '—'}  ·  ADX(14): ${lastAdx !== null ? lastAdx.toFixed(1) : '—'}`;
  } catch (err) {
    el.textContent = `Could not load indicator panel: ${err.message}`;
  }
}

renderRegimeBand();
```
